# 数据库常用命令（ptm_prod）

适用环境：当前项目使用 Docker Compose + PostgreSQL，数据库为 `ptm_prod`，schema 为 `ptm`。

下面命令默认在项目根目录执行：

```powershell
cd C:\Users\123\Desktop\测试\Soybean
```

## 1. 启动数据库

```powershell
docker compose up -d postgres
```

确认容器状态：

```powershell
docker compose ps
```

## 2. 准备导入数据

当前 `data` 目录应包含这些文件：

- `网站数据-V2-260508(1).xlsx`
- `Glycine_max_3847_PR_20250516.fasta`
- `Bradyrhizobium_diazoefficiens_PR_20250805(1).fasta`
- `修饰类型-氨基酸类型-260421(1).xlsx`

数据对应关系：

- Excel 的 `Sobean` sheet 对应 `Glycine_max_3847_PR_20250516.fasta`
- Excel 的 `Rhizobium` sheet 对应 `Bradyrhizobium_diazoefficiens_PR_20250805(1).fasta`

先把 Excel + FASTA 转成数据库导入脚本需要的 CSV：

```powershell
python .\数据处理\prepare_data_import.py --output-dir .\data\import_ready
```

生成结果：

- `data\import_ready\soybean_gs.csv`
- `data\import_ready\soybean_protein_sequence.csv`
- `data\import_ready\rhizobium_gs.csv`
- `data\import_ready\rhizobium_protein_sequence.csv`

说明：

- `*_gs.csv` 会导入到 `ptm.gs_ptm`
- `*_protein_sequence.csv` 会导入到 `ptm.protein_sequence`
- 转换脚本会自动补齐 `Organism` 字段，大豆为 `Glycine max`，根瘤菌为 `Bradyrhizobium diazoefficiens`
- 根瘤菌表中的 `AA` 列会转换为数据库需要的 `Amino acid`

## 3. 导入数据


## 4. 查看当前数据

查看总量：

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "SELECT COUNT(*) AS gs_rows FROM ptm.gs_ptm;"
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "SELECT COUNT(*) AS seq_rows FROM ptm.protein_sequence;"
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "SELECT COUNT(*) AS batch_rows FROM ptm.import_batch;"
```

按物种查看 GS 数据：

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "SELECT organism, COUNT(*) FROM ptm.gs_ptm GROUP BY organism ORDER BY COUNT(*) DESC;"
```

按修饰类型查看：

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "SELECT organism, ptm_types, COUNT(*) FROM ptm.gs_ptm GROUP BY organism, ptm_types ORDER BY organism, ptm_types;"
```

查看最近导入批次：

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "SELECT batch_id, source_type, source_name, source_version, created_at FROM ptm.import_batch ORDER BY batch_id DESC LIMIT 30;"
```

## 5. 删除数据

### 5.1 只清空 staging 表

不会影响正式表。

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "CALL ptm.clear_staging();"
```

### 5.2 按物种删除 GS 数据

删除大豆 GS 数据：

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "DELETE FROM ptm.gs_ptm WHERE LOWER(COALESCE(organism, '')) LIKE '%glycine max%' OR LOWER(COALESCE(organism, '')) LIKE '%soybean%';"
```

删除根瘤菌 GS 数据：

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "DELETE FROM ptm.gs_ptm WHERE LOWER(COALESCE(organism, '')) LIKE '%bradyrhizobium%' OR LOWER(COALESCE(organism, '')) LIKE '%diazoefficiens%';"
```

注意：`ptm.protein_sequence` 目前没有 `organism` 字段，因此蛋白序列更推荐按导入批次删除。

### 5.3 按批次删除

先查看批次：

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "SELECT batch_id, source_type, source_name, source_version, created_at FROM ptm.import_batch ORDER BY batch_id DESC LIMIT 30;"
```

再按实际 `batch_id` 删除。下面以 `8` 为例：

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "DELETE FROM ptm.gs_ptm WHERE source_batch_id = 8;"
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "DELETE FROM ptm.protein_sequence WHERE source_batch_id = 8;"
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "DELETE FROM ptm.import_batch WHERE batch_id = 8;"
```

### 5.4 清空正式表全部数据

危险操作，会删除全部 GS 和蛋白序列数据。

```powershell
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "TRUNCATE TABLE ptm.gs_ptm, ptm.protein_sequence RESTART IDENTITY;"
docker compose exec -T postgres psql -U myuser -d ptm_prod -c "DELETE FROM ptm.import_batch;"
```

## 8. 常见问题

- `Access is denied`：确认 Docker Desktop 已启动；如果命令行仍无权限，重新打开 PowerShell 或以管理员方式运行。
- `invalid byte sequence for encoding "UTF8"`：CSV 编码不是 UTF-8。优先重新执行 `python .\数据处理\prepare_data_import.py --output-dir .\data\import_ready`。
- 导入后页面没变化：重启 FastAPI 服务，或确认查询时选择了正确物种。
- `No records matched`：先执行“按物种查看 GS 数据”的 SQL，确认 `organism` 是否已经导入。
- 根瘤菌 PTM Search 没有结果：确认 `Rhizobium` sheet 已经导入，并且页面 Species 选择了 `Bradyrhizobium diazoefficiens`。
