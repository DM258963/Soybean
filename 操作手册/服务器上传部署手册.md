# 服务器上传部署手册

本文记录将本地项目上传到 Ubuntu 服务器，并作为新项目启动的完整流程。示例项目目录为：

```bash
/home/ubuntu/soybean26-6-16
```

如果你的服务器目录不同，把命令中的目录替换成实际目录。

## 1. 停止旧项目

先查看旧项目是否还在运行：

```bash
ps -ef | grep uvicorn
sudo ss -ltnp | grep :5000
```

如果旧项目由 systemd 管理，先停止：

```bash
sudo systemctl stop soybean-ptm
```

如果端口 5000 仍然被占用，根据输出中的 PID 停止进程：

```bash
kill PID
```

如果仍然停不掉：

```bash
kill -9 PID
```

确认端口已经释放：

```bash
sudo ss -ltnp | grep :5000
```

没有输出表示 5000 端口已经空闲。

## 2. 上传新项目

将本地项目上传到服务器，例如目录名为：

```bash
soybean26-6-16
```

上传后进入项目目录：

```bash
cd ~/soybean26-6-16
```

确认关键文件存在：

```bash
ls
```

应能看到：

```text
app.py
docker-compose.yml
数据处理/import_ptm_csv.py
requirements.txt
deploy/postgres/initdb/
data/import_ready/
data/
soybean_app/web/templates/
soybean_app/web/static/
```

其中 `data/` 目录需要包含两个蛋白定量表格文件，网站会在 Protein/BLAST 详情页直接读取这些 Excel 文件生成定量图，不需要导入数据库：

```text
data/Dataset S1-Soybean-DA-mean.xlsx
data/Dataset S2-Rhizobia-DA-mean.xlsx
```

## 3. 安装 BLAST+

PTM BLAST 功能依赖 `blastp` 和 `makeblastdb`。

```bash
sudo apt update
sudo apt install ncbi-blast+
```

检查是否安装成功：

```bash
blastp -version
makeblastdb -version
```

## 4. 创建 Python 虚拟环境

如果项目目录中没有 `.venv`，先创建：

```bash
python3 -m venv .venv
```

如果提示缺少 venv 模块，先安装：

```bash
sudo apt install python3.10-venv
python3 -m venv .venv
```

激活虚拟环境：

```bash
source .venv/bin/activate
```

安装依赖：

```bash
pip install -r requirements.txt
```

## 5. 启动 PostgreSQL 数据库

项目使用 Docker Compose 启动 PostgreSQL：

```bash
docker compose up -d postgres
```

查看数据库状态：

```bash
docker compose ps
```

等待数据库初始化完成：

```bash
docker compose logs --tail=80 postgres
```

看到类似下面内容后再导入数据：

```text
database system is ready to accept connections
```

也可以用：

```bash
docker compose exec postgres pg_isready -U myuser -d ptm_prod
```

输出 `accepting connections` 表示可以继续。

如果是更新已有服务器数据库，或者 `ptm_prod` 已经创建过，执行一次用户权限表迁移：

```bash
docker compose exec -T postgres psql -U myuser -d ptm_prod -f /docker-entrypoint-initdb.d/10-auth-users.sql
```

如果同时需要首页访问量统计表，也可以执行：

```bash
docker compose exec -T postgres psql -U myuser -d ptm_prod -f /docker-entrypoint-initdb.d/09-site-metric.sql
```

## 6. 导入数据

注意：Ubuntu Bash 换行符是反斜杠 `\`，不是 Windows PowerShell 的反引号。

导入大豆数据：

```bash
python ./数据处理/import_ptm_csv.py \
  --gs-csv ./data/import_ready/soybean_gs.csv \
  --protein-csv ./data/import_ready/soybean_protein_sequence.csv \
  --gs-source-name soybean \
  --protein-source-name soybean_fasta
```

导入根瘤菌数据：

```bash
python ./数据处理/import_ptm_csv.py \
  --gs-csv ./data/import_ready/rhizobium_gs.csv \
  --protein-csv ./data/import_ready/rhizobium_protein_sequence.csv \
  --gs-source-name rhizobium \
  --protein-source-name rhizobium_fasta
```

上面两条命令只导入 `data/import_ready/` 中的 PTM 位点和蛋白序列 CSV。两个蛋白定量表格保留在 `data/` 目录即可，程序运行时会读取：

```text
data/Dataset S1-Soybean-DA-mean.xlsx
data/Dataset S2-Rhizobia-DA-mean.xlsx
```

如果提示数据库刚启动还没准备好，等待 10-30 秒后重新执行导入命令。

## 7. 临时启动网站测试

确认虚拟环境已激活：

```bash
source .venv/bin/activate
```

启动 Web 服务：

```bash
uvicorn app:app --host 0.0.0.0 --port 5000
```

浏览器访问：

```text
http://服务器IP:5000
```

测试通过后，按 `Ctrl+C` 停止临时服务。

## 8. 配置 systemd 后台运行

编辑服务文件：

```bash
sudo nano /etc/systemd/system/soybean-ptm.service
```

内容设置为：

```ini
[Unit]
Description=Soybean PTM Viewer
After=network-online.target docker.service
Requires=docker.service

[Service]
User=ubuntu
Group=ubuntu
SupplementaryGroups=docker
WorkingDirectory=/home/ubuntu/soybean26-6-16
ExecStart=/home/ubuntu/soybean26-6-16/.venv/bin/uvicorn app:app --host 0.0.0.0 --port 5000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

保存 nano：

```text
Ctrl + O
Enter
Ctrl + X
```
# 然后执行

python3 -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
python -m pip install -r requirements.txt

sudo systemctl daemon-reload
sudo systemctl restart soybean-ptm
sudo systemctl status soybean-ptm --no-pager

重新加载 systemd：

```bash
sudo systemctl daemon-reload
```

启动服务：

```bash
sudo systemctl restart soybean-ptm
```

设置开机自启：

```bash
sudo systemctl enable soybean-ptm
```

查看状态：

```bash
sudo systemctl status soybean-ptm --no-pager
```

看到下面状态表示运行成功：

```text
Active: active (running)
```

## 9. 常用维护命令

停止网站：

```bash
sudo systemctl stop soybean-ptm
```

重启网站：

```bash
sudo systemctl restart soybean-ptm
```

查看网站状态：

```bash
sudo systemctl status soybean-ptm --no-pager
```

查看网站日志：

```bash
journalctl -u soybean-ptm -f
```

查看端口占用：

```bash
sudo ss -ltnp | grep :5000
```

查看 uvicorn 进程：

```bash
ps -ef | grep uvicorn
```

## 10. 部署后检查

部署完成后建议检查：

- 首页是否正常打开
- Protein Search 是否能查询
- PTM Search 是否能查询
- PTM BLAST 是否能运行
- CSV 下载是否正常
- Site Quantification PNG 下载是否正常
- `/login` 是否能登录管理员账号
- `/admin/users` 是否能创建、修改、删除测试账号
- `PTM_DOWNLOADS_ENABLED=false` 时，匿名用户是否看不到下载入口，测试账号是否可下载
- Protein/BLAST 详情页的定量图是否正常显示，缺图时先确认 `data/Dataset S1-Soybean-DA-mean.xlsx` 和 `data/Dataset S2-Rhizobia-DA-mean.xlsx` 已上传
- Raw Data 页面是否能打开

## 11. 注意事项

- 如果是全新数据，建议不要复用旧项目的 `runtime/pg_data/`。
- `deploy/postgres/initdb/` 里的 SQL 只会在 PostgreSQL 第一次初始化空数据目录时自动执行。
- `runtime/blastdb_cache/` 可以不用上传，第一次运行 BLAST 时会自动生成。
- `data/` 里的两个 `Dataset S*-*-DA-mean.xlsx` 是运行时读取的定量表格，不会通过 `数据处理/import_ptm_csv.py` 导入数据库，部署时必须随项目一起上传。
- 如果 5000 端口被占用，先用 `sudo ss -ltnp | grep :5000` 查占用进程。
- 如果服务被 systemd 自动拉起，必须用 `sudo systemctl stop soybean-ptm` 停止，而不是只 `kill` 进程。
